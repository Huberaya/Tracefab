Trust & Security

Supply chain data is sensitive by nature. TRACEFAB is built so that every datum has an owner, a status, a proof trail — and no path across tenants.

01

Tenant isolation by design

Multi-tenancy is enforced at the database level: Row Level Security is enabled and forced on tenant tables, and the API always resolves the caller's organization from a verified session.

02

Server-verified authentication

Sessions are verified server-side against the identity provider, with an explicit allow-list of authorized origins. No trust is placed in client-provided identity.

03

Private evidence storage

Documents live in private object storage, accessed only through short-lived signed URLs issued by the API after a tenant check, with SHA-256 hashing and an antivirus scan contract on upload.

04

Declarations ≠ evidence ≠ certification

Every data point carries an explicit status — declared, documented, verified, third-party certified, needs review or expired. The interface never blurs these levels.

05

Append-only audit log

Sensitive operations write who, what, when, before and after into an append-only audit trail scoped per organization.

06

Durable notification pipeline

Notifications flow through a transactional outbox processed by a secret-protected worker, with delivery observability and alerting.

07

Hardened edge

Strict security headers (HSTS, CSP, nosniff, frame deny), no-store API responses and controlled error mapping keep infrastructure details private.

08

Readiness, never certification

TRACEFAB measures DPP and data readiness. It never claims legal compliance for a brand — regulatory responsibility stays with the economic operator.

Security questions? Our team answers architecture, isolation and processing questions on request.
