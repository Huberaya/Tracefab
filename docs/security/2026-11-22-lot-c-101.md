## 4 bis. La CI a contredit ma décision sur `test:mission-ui:states`

J'avais mis cette suite dans la boucle en raisonnant ainsi : les suites
navigateur y sont déjà, Chromium est installé avant la boucle, donc elle y a sa
place. **La CI m'a donné tort, et elle avait raison.**

Résultat réel du job : **1/6 contrôles**, avec cinq échecs de cette forme :

```
ECHEC documents : erreur explicite avec code et reessai
   -> waiting for locator('[data-action="retry-documents"]').first()
ECHEC depot : formulaire reel, aucun faux succes
   -> waiting for locator('[data-action="open-upload-document"]')
ECHEC apercu DPP : brouillon PRIVE, donnees persistees, champs manquants
   -> waiting for locator('[data-action="open-dpp-preview"]').first()
```

**Aucun des trois `data-action` n'existe dans `assets/`.** Vérifié :

| Sélecteur attendu par le test | Présent dans l'interface ? |
|---|---|
| `retry-documents` | **non** |
| `open-upload-document` | **non** |
| `open-dpp-preview` | **non** |

**Le lot A a livré les routes, pas l'interface.** L'Evidence Centre, le
formulaire de dépôt et le bouton d'aperçu DPP sont le travail d'un autre lot
(#101 les contenait, répartis ailleurs). La suite est donc juste : elle constate
que l'interface n'existe pas. C'est le **câblage** qui était faux, pas le test.

**Décision : la suite est retirée de la boucle, le fichier reste dans le dépôt.**

Raison : la laisser dans la boucle rendrait la CI rouge **pour une raison
légitime mais connue** — un travail non encore fait — et transformerait un rouge
permanent en bruit qu'on apprend à ignorer. C'est exactement le mécanisme qui a
laissé #119, #118 et #91–#94 pourrir : un test rouge qu'on ne peut pas réparer
sur-le-champ finit par être contourné.

La commande est retirée de `package.json`. Elle sera rétablie en même temps que
l'interface, pas avant. **Je note ici qu'elle est en attente, pas qu'elle est
inutile.**

## 6. Ce que j'ai tenté et qui a échoué

**Faire tourner `test_mission_http_integration.mjs`.** C'est la suite la plus
précieuse du lot C : elle prouve les parcours A à F — produit créé et relu,
dépôt scanné, décision acceptée/rejetée, **aperçu DPP privé**, refus
inter-locataires, EICAR rejeté. Autrement dit, tout ce que le lot A vient
d'écrire.

Monté pour cela : un PostgreSQL 18.7 **réel** sur socket TCP via
`@electric-sql/pglite-socket`, rôles `tracefab_app` / `tracefab_migrator` /
`tracefab_ci_admin`, base créée, `db:deploy:throwaway` en mode `fidele`.

**Échec à la racine :** PGlite n'accepte **qu'une connexion à la fois**. Testé :

```
2 connexions simultanees -> ECHEC: Connection terminated unexpectedly
```

La suite fait tourner le vrai serveur HTTP *et* le client Prisma *et* le
runner de migrations en parallèle. Un serveur mono-connexion ne peut pas la
servir. **Abandonné, et non contourné : je n'ai pas réécrit la suite pour
qu'elle passe.**
