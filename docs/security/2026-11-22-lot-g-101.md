# Lot G de la PR #101 — documentation et captures : rien à récupérer, et une voie à ne pas rouvrir

Date : 2026-11-12 · Base : `main` = `55ae2df` · Tête mesurée : `48a4279` (PR #101)
Base de fusion réelle : `bf55f2a` (PR #100).
Portée : 11 fichiers, dont 9 de documentation, 2 captures PNG.

**Verdict : ne rien récupérer.** Le lot G contient deux fichiers à contenu
opérationnel, et l'un des deux **rouvrirait une voie d'exécution privilégiée**
que `main` a explicitement fermée.

## 1. Une précision de méthode

La première mesure de ce lot a été fausse. Comparer #101 à `main` **actuel**
affichait 116 fichiers et 24 019 lignes supprimées — mais ce diff mesurait les 15
PR fusionnées depuis, pas ce que #101 change. La comparaison correcte est
`base de fusion → tête de #101`.

Elle a d'abord renvoyé une base vide, ce qui laissait croire que #101 n'avait
aucun ancêtre commun avec `main`. Cause : le clone est **superficiel**
(`.git/shallow`). Après `git fetch --deepen=2000`, la base réelle apparaît :
`bf55f2a`, la fusion de la PR #100.

Le vrai diff du lot G est donc de **11 fichiers, +1232 / −8**.

## 2. Les captures et les récits : sans valeur de décision

Sept des onze fichiers sont des rapports de mission datés (`livrables-finalisation/`,
`docs/…/mission-finalisation-2026-10-26/`) et deux captures PNG. Ils décrivent un
état de la mission #101 à sa date de rédaction. Aucun n'est chargé par
l'application, aucun n'est lu par un test. Les reprendre sur `main` reviendrait à
archiver un récit périmé : les lots A à F ont depuis bougé ce qu'ils décrivent.

## 3. `docs/operations/variables-environnement.md` : déjà couvert par `main`

`main` a reçu ce document dans le lot A (`b00af4e`). Mesure : **toutes** les
variables documentées par la version de #101 sont déjà documentées sur `main` —
zéro manquante (`comm -23` sur les deux listes de variables).

Les ajouts de #101 que `main` n'a pas mot pour mot sont les paragraphes sur
l'adaptateur PostgreSQL de Preview (`TF_PREVIEW_STORAGE_TEST_ONLY`,
`…_DB_FINGERPRINT`, `…_LOCAL_TEST`, `…_LOCAL_ORIGIN`). Ces variables **existent
bel et bien sur `main`** — vérifié dans `api/` et `scripts/` (6, 4, 5 et 5
fichiers). Le code est là ; seule la prose de #101 est plus détaillée sur ce
point précis.

**Ce n'est pas un manque de sécurité** : rien dans ce paragraphe ne conditionne
un comportement. C'est un enrichissement de documentation, à reprendre
séparément s'il est souhaité — pas un lot à fusionner.

## 4. `workflow-privileged-allowlist.json` : `main` est strictement plus sûr

C'est le fichier qui compte, et c'est là que le lot G est dangereux.

`main` a **supprimé** le déclencheur `push` de `preview-http-journeys.yml`. Le
workflow ne part plus que sur `workflow_dispatch`. Son en-tête le dit :

```
# POURQUOI IL N'Y A PLUS DE DECLENCHEUR `push`
# Le declencheur `push` a ete SUPPRIME, pas desactive : une voie fermee par une
# variable peut etre rouverte par la meme variable.
```

La tête de #101 fait exactement l'inverse :

```yaml
on:
  push:
    branches:
      - 'arena/647ac97c-tracefab'
…
if: ${{ github.ref == 'refs/heads/arena/647ac97c-tracefab' && (github.event_name == 'workflow_dispatch' || (github.event_name == 'push' && vars.TF_PREVIEW_PUSH_ENABLED == '1')) }}
```

Le commentaire justificatif de #101 est explicite : « Comme cette PR ne doit pas
être fusionnée, le push est une voie alternative ». C'était cohérent tant que
#101 vivait sur sa branche. **Fusionner le lot G importerait cette voie sur
`main`.**

### Mesure du garde

`npm run test:workflow-policy` sur le registre de `main` : **vert**. En y
substituant le registre de #101 : **14 échecs**, dont

```
ECHEC A. lit secrets.CLERK_SECRET_KEY sans etre declare au registre
ECHEC F. job rattache a tracefab-clerk-test sans declaration au registre
ECHEC D. demande contents: write sans declaration au registre
ECHEC J. permission contents: write non minimale dans job publier-preuves
```

Le registre de #101 ne décrit donc plus les workflows de `main` : il décrit
l'état antérieur. Le garde le dit, précisément et sans ambiguïté. Le lot G n'est
pas « mécaniquement récupérable » — il est **incompatible avec l'état durci de
`main`**.
