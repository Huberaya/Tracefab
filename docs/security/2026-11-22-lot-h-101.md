**Verdict : une ligne sur trois fichiers.** Le lot H contient un vrai défaut de
câblage sur `main` — un script de test présent, documenté, et **appelable par

## 1. Le défaut réel : `test:mission-ui:states` n'existe pas

`scripts/test_mission_ui_real_states.mjs` est présent sur `main`. Son en-tête
déclare son propre mode d'emploi :

```
 * Usage : npm run test:mission-ui:states
```

Cette commande **n'existe pas** dans le `package.json` de `main` — vérifié par
`grep '"test:mission-ui:states"'` : aucune correspondance. Le script n'est pas
non plus appelé par une étape de CI, ni sur `main` ni sur la tête de #101
(`grep` sur `.github/workflows/` : aucune occurrence).

C'était cohérent avec l'état ancien : le script échouait parce que l'interface
visée n'était pas encore extraite du HTML dans `assets/`. Le lot E livre ce
`assets/` ; le script devient donc exécutable, et il reste **sans porte
d'entrée**. C'est précisément ce que le lot H fournit.

### Mesure

| Élément | `main` | #101 |
|---|---|---|
| `scripts/test_mission_ui_real_states.mjs` | présent | présent |
| entrée `package.json` | **absente** | présente |
| appel CI | aucun | aucun |

La dernière ligne est une limite de cet environnement, pas du script : il
s'arrête dans `launch_chromium.mjs` parce qu'aucun navigateur n'est installé ici.
**Ce n'est pas une preuve que le script est vert** — seulement qu'il démarre et
qu'il atteint la couche navigateur, ce qui est le plus loin qu'on puisse aller
sans `npx playwright install chromium`.

**Ajouté sur cette branche :** la seule ligne
`"test:mission-ui:states": "node scripts/test_mission_ui_real_states.mjs"`.
Vérifié : la commande apparaît dans `npm run`, pointe sur le bon fichier, et
s'exécute jusqu'à l'échec navigateur attendu. Rien d'autre n'a été repris.

## 2. Ce qu'il ne faut pas reprendre : `db:generate:offline`

#101 ajoute `"db:generate:offline": "node scripts/db-generate-offline.mjs"`.
`main` a **déjà** cette commande, pointant sur un autre fichier :

```
main :  "db:generate:offline": "node scripts/generate_prisma_client_offline.mjs"
#101 :  "db:generate:offline": "node scripts/db-generate-offline.mjs"
```

`scripts/db-generate-offline.mjs` **n'existe pas** sur `main`. Reprendre la ligne
de #101 casserait la commande. Celle de `main` fonctionne — exécutée pour de
vrai :

```
Client Prisma genere hors ligne dans node_modules/.prisma/client (index.d.ts, 7891 Ko).
Types complets, moteur de requete absent : ce client sert au typecheck, pas aux requetes.
```

C'est un cas où le même nom de commande désigne deux implémentations : sans
exécution, la reprise aurait été un remplacement silencieux d'un outil qui
marche par un fichier inexistant.
