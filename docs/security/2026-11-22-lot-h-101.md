# Lot H de la PR #101 — `package.json`, `.env.example`, `.gitignore` : rien à reprendre tel quel

Date : 2026-11-12 · Base : `main` = `55ae2df` · Tête mesurée : `48a4279` (PR #101)
Base de fusion réelle : `bf55f2a`.
Portée mesurée : `package.json`, `.env.example`, `.gitignore`.

**Verdict : ne rien récupérer.** J'ai d'abord cru le contraire, ajouté une ligne,
et la CI m'a démenti — c'est la partie utile de ce document.

## 1. Le défaut apparent, et pourquoi il n'est pas réparable seul

`scripts/test_mission_ui_real_states.mjs` est présent sur `main`. Son en-tête
déclare son propre mode d'emploi :

```
 * Usage : npm run test:mission-ui:states
```

Cette commande **n'existe pas** dans le `package.json` de `main` — et aucune
étape de CI ne l'appelle. Le script paraissait donc orphelin, et la ligne
manquante un correctif évident. **C'est faux, et je l'ai mesuré à mes dépens.**

### Ce qui s'est passé

La ligne ajoutée, la CI a immédiatement échoué — sur ce même script :

```
suites en echec : test:mission-ui:states

ECHEC documents : erreur explicite avec code et reessai
        -> locator.click: Timeout 30000ms exceeded.
Call log:
  - waiting for locator('[data-action="retry-documents"]').first()

ECHEC documents : etat vide distinct de "non calcule"
        -> waiting for locator('[data-action="retry-documents"]')

ECHEC depot : formulaire reel, aucun faux succes
        -> waiting for locator('[data-action="open-upload-document"]')
```

Pourquoi la CI l'a lancé : elle **boucle sur tous les `test:*` du
`package.json`** (`ci.yml`, ligne 619). Ajouter une entrée de script, c'est
inscrire la suite au programme. La ligne n'était pas une déclaration inerte :
c'était une mise en service.

### Pourquoi il échoue

Les sélecteurs attendus par le script n'existent pas dans les bundles de `main` :

| Sélecteur attendu | `main` | tête #101 |
|---|---|---|
| `data-action="retry-documents"` | **0** | 3 |
| `data-action="open-upload-document"` | **0** | 2 |
| `data-action="review-document"` | **0** | 1 |

Ce sont exactement les actions **ajoutées par le lot E** (§4 du document du lot
E). `scripts/test_mission_ui_real_states.mjs` est le **garde du lot E** : il
vérifie les états du nouvel écran de documents — chargement, erreur avec code et
reprise, état vide, dépôt réel, aperçu privé.

Le script n'est donc pas orphelin par oubli : il est **en avance sur les
bundles**. Lui donner une porte d'entrée sur `main` revient à brancher un garde
sur un écran qui n'existe pas encore.

**Conclusion : la ligne se reprend avec le lot E amendé, pas avant.** Elle est
d'ailleurs la meilleure raison de l'amender : c'est la seule preuve navigateur
que le nouvel écran fonctionne réellement.

## 2. `db:generate:offline` : même nom, deux implémentations

#101 ajoute `"db:generate:offline": "node scripts/db-generate-offline.mjs"`.
`main` a **déjà** cette commande, pointant sur un autre fichier :

```
main :  "db:generate:offline": "node scripts/generate_prisma_client_offline.mjs"
#101 :  "db:generate:offline": "node scripts/db-generate-offline.mjs"
```

`scripts/db-generate-offline.mjs` **n'existe pas** sur `main`. Reprendre la ligne
de #101 casserait la commande. Celle de `main` fonctionne — exécutée pour de
vrai :

```
Client Prisma genere hors ligne dans node_modules/.prisma/client (index.d.ts, 7891 Ko).
Types complets, moteur de requete absent : ce client sert au typecheck, pas aux requetes.
```

Sans exécution, la reprise aurait remplacé silencieusement un outil qui marche
par un fichier inexistant.

## 3. Ce qui n'existe pas, ou ne vaut pas une reprise

- `.gitignore` : **aucun changement** entre `bf55f2a` et la tête de #101.
- `.env.example` : #101 ajoute `PRIVATE_STORAGE_BACKEND=s3` et deux lignes de
  commentaire. La variable est **déjà** sur `main`, documentée dans
  `docs/operations/variables-environnement.md` (lot A, `b00af4e`) et présente
  dans 7 fichiers. Elle a un défaut (`s3`) : son absence de `.env.example` ne
  casse rien. Clarification utile, non critique, non reprise ici.

Les quatre autres commandes de #101 — `test:neon:mission-functional`,
`test:preview-harness`, `test:preview-storage-guards`,
`test:neon:preview-postgres-storage` — **existent déjà** sur `main` avec leurs
cibles présentes. Aucune reprise nécessaire.

## 4. La leçon générale

Le lot H était annoncé « divers : `package.json`, `.env.example`, `.gitignore` »,
c'est-à-dire le lot le plus anodin du découpage. Il contenait pourtant le piège
le plus coûteux : **une entrée de script n'est pas de la configuration, c'est une
mise en service.** Dans un dépôt dont la CI exécute tous les `test:*` par
découverte, ajouter une ligne au `package.json` suffit à faire tourner une suite
entière — et à faire échouer la CI sur un manque qui n'est pas celui qu'on
croyait corriger.

Ce document est le seul des quatre dont la conclusion a été **renversée par une
mesure** : la mienne, la vraie, celle de la CI.
