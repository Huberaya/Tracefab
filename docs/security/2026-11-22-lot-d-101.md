# Lot D de la PR #101 — i18n : rien à récupérer

Date : 2026-11-12 · Base : `main` = `d41cdbd` · Tête mesurée : `48a4279` (PR #101)
Portée : `assets/i18n/{en,fr,de,it,es,nl,pt}.js` — 7 fichiers, 7 langues.

**Décision proposée : ne rien récupérer du lot D. `main` est strictement supérieur
sur les sept fichiers.** Les raisons sont mesurées ci-dessous.

## 1. Le découpage §2 était faux sur ce lot

Le découpage rangeait le lot D dans « mécaniquement récupérable » : #101 change
56 clés, ces changements sont identiques dans les sept langues, donc supposément
neutres. Ce raisonnement ne tient pas, parce qu'il ne regarde que le **diff entre
locales** et jamais le **lien entre le catalogue et le code**.

#101 retire 56 clés de la portée `console`. **53 d'entre elles étaient appelées
par les bundles de `main`.** Une clé retirée du catalogue et toujours appelée ne
provoque aucune erreur : le traducteur rend la clé brute.

```js
function bt(key) {
  const T = window.TF_I18N;
  if (!T) return key;
  return T.t('console.' + key, null) || T.t('shared.' + key, key);
}
```

`t()` échoue sur `console.<clé>`, retombe sur `shared.<clé>`, échoue encore, et
rend `key`. L'interface affiche `docAvailableLabel` là où elle affichait
« Disponibles ». C'est un défaut silencieux : aucune exception, aucun test rouge,
rien dans la console du navigateur.

## 2. Les 53 clés ne sont pas du bruit

Elles sont groupées, et chaque groupe correspond à un écran :

| Préfixe | Écran | Exemples |
|---|---|---|
| `doc*` | dépôt et état d'un document (disponible / expiré / scanné / rejeté) | `docAvailableLabel`, `docExpiredDesc`, `docScanningDesc`, `docUploadGo` |
| `dpIdentity*` | identité publique du passeport | `dpIdentityTitle`, `dpIdentityQr`, `dpIdentityPublicId` |
| `dpPublication*` | **publication, suspension, retrait du passeport** | `dpPublicationPublish`, `dpPublicationSuspend`, `dpPublicationWithdraw` |
| `px*` | activation produit | `pxActivate`, `pxActivateConfirm` |
| `ev*` | vérification d'une preuve | `evVerify`, `evDownload` |
| divers | aide et garde-fous | `mdProcessOnlyForProcess`, `dpNodeDocumentHelp` |

Ce ne sont pas des libellés orphelins : ce sont les commandes qui rendent un
passeport publiable et ses preuves vérifiables.

## 3. Ce que #101 apporte réellement

Il serait faux de dire que #101 supprime sans rien livrer. Le lot E de la même PR
réécrit `brand-console.1.js` et `supplier-portal.1.js` : il retire 53 appels et en
ajoute 47 (`dcAccept`, `dcDownload`, `mdClose`, `dcAcceptReason`…).

**Ces 47 nouvelles clés sont toutes présentes dans le catalogue de #101** —
vérifié, 0 manquante. #101 est donc cohérent avec lui-même : il livre un couple
bundles + catalogue qui se tient. Le problème n'est pas l'incohérence, c'est la
**disparition d'écrans existants** : dépôt de document, identité publique,
publication du passeport, activation produit, vérification de preuve. Récupérer
le lot D sans le lot E laisserait des clés orphelines ; récupérer D avec E
supprimerait ces écrans. Aucune des deux branches n'est un gain.

## 4. Le générateur n'y est pour rien

`scripts/build_app_i18n.mjs` fait `base.console = built[lang].console`, un
remplacement total de portée. Sur `main`, exécuté pour de vrai :
**1180 clés avant, 1180 après, 0 perdue.** La perte vient du contenu de #101,
pas de l'outil qui le construit. Il n'y a donc pas de correctif à apporter au
générateur.

## 5. L'angle mort qui a rendu ce défaut invisible

`npm run test:i18n` était **vert sur la tête de #101**. C'est ce qui a laissé
passer le lot D. Le script compare les catalogues entre eux : il détecte une clé
perdue par une langue, jamais une clé perdue par les sept — or c'est précisément
la forme du défaut.

Le contrôle manquant est ajouté dans cette branche. Il relève les `bt('…')`
réellement appelés par `assets/*.js`, puis exige que chaque clé existe dans
`console` **ou** `shared` (le repli de `bt`) pour les sept catalogues. Éprouvé
dans les deux sens :

| | Clés relevées | Résultat |
|---|---|---|
| `main` | 987 | **vert** — les 987 sont couvertes |
| tête de #101 | 981 | **rouge** — `mdClose` absente |

Le garde attrape la classe de défaut ; il n'attrape pas la régression elle-même
sur #101, parce que #101 supprime simultanément les appels et les clés. Il ne
remplace donc pas la lecture du lot E : il empêche que le même angle mort serve
une seconde fois.

## 6. Relevé chiffré

| | `main` (`d41cdbd`) | #101 (`48a4279`) |
|---|---|---|
| Clés de la portée `console` | **1180** | **1162** |
| Clés `bt(...)` appelées | **987** | **981** |
| Appelées et introuvables | **0** | **0** (mais 53 appelées par `main` ne le sont plus) |
| Clés appelées par `main`, plus par #101 | — | **53** |
| Clés nouvellement appelées, toutes au catalogue | — | **47** |
| Clés supprimées au total | — | **56**, à l'identique dans les 7 langues |

## 7. Recommandation

Fermer #101, ou la réduire au seul lot E **après revue de ce que la suppression
des écrans implique fonctionnellement** — question qui dépasse l'i18n et que ce
document ne tranche pas. Ne récupérer aucun des sept fichiers de catalogue.

Réserve : `scripts/build_app_i18n.mjs` n'est couvert par aucun contrôle de
non-régression sur la portée `console`. L'exécuter sur `main` rétablit le compte,
mais un futur contenu défaillant passerait encore. Le garde du §5 couvre les clés
appelées, pas les clés jamais appelées.
